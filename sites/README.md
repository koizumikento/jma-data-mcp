# JMA MCP on Sites

This directory is a **Sites Worker ESM package**, with stateless `POST /mcp`.
It forwards MCP messages to the existing Python implementation. A separate
Python backend is required; Sites alone does not run this package's Python code.
All eleven tools, schemas, descriptions, structured/text results, station
snapshot, pagination, defaults, domain errors, units, timestamps and JMA source
data stay owned by `jma_data_mcp/server.py`, `stations.py` and `weather.py`.
No JMA API key, writable storage, D1, R2 or new Node dependencies are needed.

## Why a backend

Sites runs Cloudflare Worker ESM with HTTP external connections. Reimplementing
the Python parsing in JavaScript would duplicate the contract. In addition,
`get_weather_time_series(hours=168, interval_minutes=10)` makes up to 1,008
sequential JMA map requests. Moving it behind one Worker HTTP request preserves
the existing 168-hour range and partial-result/retention semantics. The backend
uses stateless Streamable HTTP with JSON responses. The locked legacy client's
SSE event size limit cannot carry a full fixture series, so JSON keeps large
results intact. The Worker forwards the response body without transforming it
and can also forward SSE. It does not add sessions, retries or truncate results.

## Local checks (no real JMA or Sites calls)

From the repository root, with Python 3.10+ / `uv` and Node 22+ installed:

```sh
uv sync --frozen
uv run ruff check .
uv run mypy jma_data_mcp
uv run pytest -m "not integration"
uv build
npm --prefix sites test
npm --prefix sites run build
npm --prefix sites run validate
```

The HTTP contract tests start the real backend and a Node Worker harness on
random loopback ports, mock only outbound JMA fetches, and terminate both servers
in `finally`. The harness emulates Dispatch identity and rewrites the fixed
HTTPS backend URL to loopback **only in tests**. It is not a deployment server.
The synthetic fixture `tests/fixtures/sites-weather.json` is authored test data;
the station data remains the repository's JMA-derived 1,286-station snapshot.
Fixture clock: `2026-10-10T12:20:00+09:00`.

Both modern (`2026-07-28`) and legacy handshake clients are checked with the
locked FastMCP 4.0.11 / MCP Python SDK 2.2.0. Discovery metadata and all tool
results are compared against the original in-process server. This verifies
transport/contract behavior, not model routing or a hosted client connection.

| Fixture task | Related calls and assertion |
| --- | --- |
| RO-01 | `search_stations` → `get_station_info`: Japanese/kana/English resolution and stable station code |
| RO-02 | `search_nearby_stations` → `get_weather_by_location`: distance ordering, selected station, empty 100 km scope |
| RO-03 | `list_stations` → `get_station_info`: offset/limit and terminal page against the same snapshot |
| RO-04 | `list_prefectures` → `get_forecast`: existing area keys, raw issuing office/time, unknown prefecture error |
| RO-05 | `get_current_weather` → `get_historical_weather` → `get_weather_time_series`: zero vs missing, units/JST, invalid date/interval, partial 404 retention and full 1,008-point range |

The deterministic tests cover each surface and compare raw results; this table
also defines later agent acceptance tasks. A clean-context model evaluation and
live retention/latency checks have not been run. No mutation tools are exposed.

## Backend deployment

Use an existing Python host reachable from Sites over HTTPS. Do not publish the
Node test harness. Supply `JMA_BACKEND_TOKEN` as a runtime secret generated by
your secret manager (at least 32 random visible ASCII characters). The same
value goes into the Site secret; never place it in commands, tracked files,
logs, manifests or prompts. `.env.example` lists names only.

Run from the repository root after `uv sync --frozen`:

```sh
uv run uvicorn jma_data_mcp.sites_backend:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log
```

The factory refuses to start without the secret. Every backend HTTP request,
including discovery, requires `Authorization: Bearer <runtime secret>`. This
authenticates the **service**, not a ChatGPT visitor. Browser `Origin` requests
are rejected. The original `jma-data-mcp`, Python library, CLI and stdio entry
points remain available with their existing behavior.

Expose **only `/mcp`** through your existing HTTPS reverse proxy. For nginx, the
MCP location inside an existing TLS virtual host can use:

```nginx
location = /mcp {
    proxy_pass http://127.0.0.1:8000/mcp;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_set_header Host $host;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 11000s;
    proxy_send_timeout 11000s;
}
```

Keep TLS verification enabled. A private/local backend requires an existing
stable HTTPS reverse proxy or a supported HTTP tunnel, such as a named
[Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/),
mapping its hostname to `http://127.0.0.1:8000`; the backend service secret remains
required even through a tunnel. Raw TCP, localhost URLs and private-LAN URLs are
not reachable from Sites. Sites' service-access token belongs to that Site and
must not be sent to this backend. This PR creates no host, tunnel or account.

Large series remain sequential and may take minutes. JSON arrives when the tool
finishes, so client call/read timeouts and host/tunnel idle/request limits must
allow the requested range. The proxy example permits the worst-case budget of
1,008 × 10-second upstream timeouts; a Site or client may impose a smaller limit.
Check those limits before production use. Hosted 168-hour performance is
unverified; the offline fixture proves the complete range without reducing it.

## Sites source, secrets and publication

The build follows the official Worker ESM starter layout:

```text
sites/dist/server/index.js
sites/dist/.openai/hosting.json
```

Only the Worker and manifest are deployed; Python and station data stay on the
backend. There are no client assets or credentials in the bundle.

When publication is authorized, use the official Sites workflow:

1. Select/create an owner-private Site and open its source checkout with the
   Sites source helper. Copy `worker/`, `scripts/`, and `package.json` from this
   directory into that **separate** source checkout. Do not change this GitHub
   repository's remote to a Sites source URL.
2. Preserve the selected Site's `.openai/hosting.json` identity, access policy,
   storage bindings and existing capabilities. Add `"mcp"` to `capabilities`.
   For a fresh Site use this directory's manifest, then run the official
   `scripts/set-project-id.mjs --project-id <returned Site ID>` helper from the
   Sites plugin. The tracked template intentionally has no invented Site ID.
3. Configure runtime secrets through the native Sites secret tools:
   `JMA_BACKEND_URL` (the exact `https://<backend-host>/mcp` URL, without
   credentials/query/fragment) and `JMA_BACKEND_TOKEN`. The URL is an
   administrator setting; tool callers cannot select a destination or path.
4. Use the official Sites source helper to synchronize/package, with commands
   `["npm", "run", "build"]` then `["npm", "run", "validate"]` in the Site source
   checkout. The portable build emits the starter's Worker ESM contract; no
   Vinext build integration is needed for this starter.
5. Save/deploy the returned unchanged archive with the native Sites tools and
   preserve the private audience. Reuse the Site's App/plugin on updates.
   Sites owns OAuth, sign-in, and connection authentication.
6. Separately verify authenticated `initialize`, `tools/list` (all eleven names
   and schemas), a station lookup, and mocked or authorized JMA-backed calls
   from the target client. Deployment or plugin installation alone is not
   evidence of working discovery/calls. Keep source SHA and archive identity.

Tool calls require a nonempty `oai-authenticated-user-id` injected by trusted
Sites Dispatch. Discovery contains only public schemas; it may run without user
identity. All records are public JMA data, so no per-user storage or email-based
membership is introduced. Platform service access **without visitor identity**
does not authorize tool calls. The Worker never forwards visitor credentials,
identity, cookies or platform service-access tokens to the backend. Do not
expose the Worker directly via Wrangler or another route where clients can
forge identity headers; it is intended exclusively for Sites Dispatch.

Malformed/batched JSON, non-JSON bodies, cross-origin requests and inputs over
64 KiB are rejected. Tool arguments, protocol version/header consistency,
schemas and tool errors are validated by the existing MCP SDK at the backend.
Modern metadata headers/body and pagination cursors pass through unchanged.
GET/DELETE are 405 (no session/SSE GET endpoint). Redirects are not followed;
backend authentication/configuration/network failures return sanitized gateway
errors without credentials or backend diagnostics. Data responses are uncached.

## Verification and cleanup boundaries

CI runs the offline Python/stdio/CLI/HTTP checks and Worker tests/build. It does
not deploy Sites or contact JMA. Live JMA tests remain under `integration`.
No Site, plugin, tunnel, DB, account or production data is created by these tests.
Temporary servers use ephemeral loopback ports and shut down after each case.
Remove only the dedicated local `.venv`, cache and generated `dist` directories
created for verification after use; keep the branch, source, tests and worktree
for review. The PR report records actual execution and cleanup separately from
these reproducible instructions.

Official contracts checked 2026-10-10:
[MCP current Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http),
[MCP legacy HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports),
[MCP tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools),
[FastMCP HTTP/stateless deployment](https://gofastmcp.com/deployment/http),
and [Cloudflare limits](https://developers.cloudflare.com/workers/platform/limits/).
The installed official Sites 1.0.0 skill, `site-mcp-server.md`,
`identity-and-secrets.md`, `storage.md`, and Worker ESM starter are the authority
for Sites-specific manifest, identity and artifact shape.
